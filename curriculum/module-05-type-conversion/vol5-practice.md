# Module 5 Volume 5: Practice Exercises - Type Conversion & Casting

## Target: Java 21 LTS, IntelliJ IDEA

**Note: These are PROMPTS ONLY. No solutions are provided in this volume.**

### SMALL EXERCISES (10)
1. Write a program demonstrating ALL widening conversions: `byte` → `short` → `int` → `long` → `float` → `double`, and `char` → `int`. Print the value and its type at each step.
2. Write a program demonstrating ALL narrowing conversions with explicit casts. Show what happens with values that overflow the target type's boundaries.
3. Show that `byte + byte = int` by writing code that causes a compile error, then write the fix using an explicit cast.
4. Demonstrate compound assignment implicit casting: Show why `short s = 10; s += 5;` compiles successfully but `short s = 10; s = s + 5;` fails.
5. Show constant expression narrowing: Demonstrate that `byte b = 100` compiles, `byte b = 128` fails, and `final int X = 100; byte b = X;` compiles successfully.
6. Demonstrate precision loss: Show conversion from `int` → `float` and `long` → `double` using large values where precision is lost despite being a widening conversion.
7. Show the difference between casting and rounding: Compare `(int) 3.99` (truncation) with `Math.round(3.99)` (proper rounding).
8. Demonstrate upcasting and downcasting using `Object` and `String` references.
9. Show an `instanceof` check used before performing a safe downcast (legacy style).
10. Demonstrate binary representation of casts: Show the results of `(byte) 256`, `(byte) -129`, and `(char) -1`, and print their binary string representations to explain the result.

### MEDIUM EXERCISES (10)
1. Write a complete type conversion reference program. After compiling, use `javap -c` to show the bytecode for every widening and narrowing instruction (e.g., `i2l`, `l2i`, `i2b`).
2. Pattern matching `instanceof` demo: Refactor a legacy method containing a chain of `if-else` blocks with explicit casts to use pattern matching for `instanceof`.
3. Pattern matching `switch` (Java 21): Write a method that accepts an `Object` and handles `Integer`, `Double`, `String`, and `null` using a pattern matching `switch` expression.
4. Build a safe cast utility method: `public static <T> Optional<T> safeCast(Object obj, Class<T> type)`.
5. Demonstrate ALL special values for `float`/`double` → `int` narrowing: Show the `int` result for `NaN`, `+Infinity`, `-Infinity`, `Integer.MAX_VALUE + 1.0`, and normal values.
6. Show an autoboxing + widening chain: Demonstrate how an `int` goes to `Integer` to `Number` to `Object`, and trace the reverse process involving unboxing.
7. Demonstrate ternary type promotion: Collect 3 distinct examples where the ternary operator (`? :`) promotes the result type unexpectedly.
8. Write a program showing `ClassCastException` with enhanced messages (Java 17+ feature). Catch the exception and print its message.
9. Demonstrate array covariance and `ArrayStoreException`: Create a `String[]`, assign it to an `Object[]` reference, and attempt to store an `Integer` in it.
10. Build a universal type converter method: It should accept any `Object` and a target `Class<?>`, attempting basic conversions before returning an `Optional`.

### HARD EXERCISES (5)
1. Write a program that executes ALL 15 JVM bytecode conversion instructions. Provide comments showing the exact bytecode output from `javap`.
2. Build a type-safe heterogeneous container using Class tokens (an Effective Java pattern) that handles primitive wrappers automatically.
3. Create a comprehensive numeric overflow detector. Write utility methods that check for precision loss and overflow *before* performing any primitive narrowing conversion.
4. Demonstrate heap pollution with generics: Show exactly how unchecked casts can cause a `ClassCastException` at unexpected locations (synthetic bridge methods).
5. Write a Bridge Method Analyzer: Use reflection to find and display bridge methods generated by `javac` specifically for handling type erasure and covariant return types.

### PRODUCTION PROBLEMS (3)
1. **Financial Truncation:** A legacy financial system loses pennies on millions of transactions because it uses `(int) (dollarAmount * 100)` which truncates. Write the reproducible bug and fix it using `BigDecimal` or `Math.round`.
2. **Unsafe API Usage:** An old caching API returns `Object`. Code everywhere downcasts it without checking. Add a wrapper around the cache that uses Java 21 pattern matching to provide safe, typed retrieval.
3. **Generics Pollution:** A generic collection `List<String>` is passed to a legacy raw type method that inserts an `Integer`. This causes a `ClassCastException` deep in business logic. Write the reproducible code, diagnose, and fix it.

### REFACTORING TASKS (3)
1. Refactor a heavily overloaded method suite (handling `int`, `long`, `float`, `double` separately) to use a generic type with type bounds and pattern matching `switch`.
2. Refactor manual type checking (`if (obj.getClass() == String.class)`) to use modern Java pattern matching constructs.
3. Refactor a complex parsing utility that catches `NumberFormatException` and `ClassCastException` into a clean, functional pipeline using `Optional` and safe casting.

### DEBUGGING TASKS (3)
1. Debug a mathematical calculation where `1 / 2` evaluates to `0` instead of `0.5` due to integer division before widening.
2. Debug a loop that never terminates because a `byte` counter overflows and wraps around to negative values.
3. Debug an `equals(Object o)` method that throws `ClassCastException` when compared to an object of a different class.

### CODE COMPLETION (3)

2. Complete the generic `Extractor<T>` class that safely extracts a value of type `T` from a nested JSON-like `Map<String, Object>`.
3. Complete the Java 21 `switch` expression that formats any object: `String formatNode(Object node) { return switch(node) { ... }; }`.
